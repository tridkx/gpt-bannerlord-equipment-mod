# 问题排查与交付故障

## 游戏只有皮肤，头发和衣服不可见

先从**安装中的 TPAC** 读取 materials、meshes、Alpha 范围，与工作区包校验 SHA256。不要一开始就重建绑骨。

1. 检查 Item 的 mesh、网格 material、材质 texture 的引用。确认透明贴图解码后有有效 Alpha、正确 mip 与裁切阈值。
2. 检查使用 `alpha_test` 的材料是否还乘顶点 Alpha。若顶点 Alpha 保存布料距离，应有 `disable_vertex_color_alpha`，且在 ShaderMaterialFlags 中。
3. 典型天香故障：阈值 0.2745，而网格顶点 A 最大只有 0–28/255；标准非布料渲染路径即使纹理完全不透明也会裁掉整个部件，固定点与远 LOD 尤其明显。
4. 只改正确材质字段。对照前后网格/权重、Colors、cloth metadata 哈希，保留已接受的造型与布料。重新安装并确保安装文件就是修复后的包。

`audit_package.py` 用最大 A 推算标准渲染路径的完全裁切风险；它不会读取纹理、因子颜色或所有 shader 分支，不能证明完整透明效果。自定义 shader 或故意使用顶点透明度时按实际源码分析，避免套用布料规则。

## 加载画面后崩溃，无法进入菜单

读取本次启动的时间、版本、加载模块和最近日志；旧 dump 不能当本次故障证据。

- 日志：`C:\ProgramData\Mount and Blade II Bannerlord\logs`。
- 用户 crash dumps：`C:\Users\DKX\AppData\Local\CrashDumps`。
- 核对实际 Module 描述、XML、资产引用与安装包哈希。排查所涉依赖和原生资源读取，不从“启用新 Mod 后崩溃”直接推断模型一定损坏。

天香案例日志停在 `Body mesh name fetched jingrenou`；Native 的 `skins.xml` 与 `action_sets.xml` 有 `JJRO_BEGIN/END` 标记的旧镜人偶项，引用已不存在的资源。更早时间同类崩溃也存在，后来用户明确授权清理该旧 Mod，清理后进入游戏。这个记录用于提示调查残留，**不是自动删除其他 Mod 的规则**。

如已有明确清理授权，只处理已确认项：保存原始字节备份、文件 SHA256 与清理清单；验证 XML 语义差异只移除目标项，写入前确认文件未被别人改动。当前 `tools/repair_launch.py --apply` 只针对上述 JJRO 标记，不适用于一般启动崩溃。无明确原因时保留模块与报告，不循环改 Native、重装全部资源或重复启动游戏。

## 头颈缝隙与肩部不自然

先确定是几何裂缝还是阴影接缝。几何在静止姿态重合但动作时分离，优先比较量化权重；仅远景出现则检查相应 LOD；位置正确却有明暗边界，查 corner normals、皮肤材质和切线。

短颈不是简单下移头：检查胸椎源标记是否误放到肩高度、锁骨/颈映射是否拉长。肩部前旋采用肩支点和连续影响，检查身体、袖子是否共同变化。前后预览用相同镜头与光线，侧面尤其能判断前后位置。返修数值以用户本次要求和实际基线为准。

## 跑动时裙摆被腿/鞋穿过

检查所有运动帧，而非单张静态姿势。按大腿、小腿、脚跟分别定位；采样网格表面并观察最差帧正面和侧后方。只改善大腿代理距离时，后鞋跟仍可能穿裙。

先调整蒙皮锚点和裙摆内部间距，再收紧活动距离与惯性。更强小腿随动可以在抬脚时抬起裙边，使鞋从裙口露出；也可能产生较硬裙摆，需要预览权衡。大范围增大 Alpha 会让碰撞更难稳定，不能作为首选。

胶囊代理、开放腿部网格的有符号距离均有近似误差。天香报告里约 98% 改善属于某组代理深度统计，并非 98% 游戏穿模已消失。最终说明应标清指标和未验证的游戏物理。

## Blender 脚本显示异常，源文件贴图丢失

- 后台 Python 抛异常时 Blender 可能仍返回 0。使用 `--python-exit-code 1`，检查 traceback、退出码、产物时间戳与实际断言，不能只根据进程结束发布。
- 图片数据会延迟加载；`has_data == False` 不表示图片不存在。不要只在 `has_data` 为真时调用 pack。解析 `filepath`，找回本工程 `tex/` 原图，明确 `reload()` 后 `pack()`，检查 `packed_file`。
- FBX 导入可能留下空 filepath 或 `image.png.001` 等重复 datablock 名。只在能确定来源时去掉 Blender 重复后缀匹配原图；找不到就报告具体缺图，不绑定任意同名图。
- 保存后在新的 Blender 后台进程重新打开实际 `.blend` 验证贴图已内嵌。从 Git 提取的旧 Blend 放到别的目录后，先重定位外部贴图再渲染基线，避免粉色对比图。

## 安装包与测试版本不一致

报告写入实际 package SHA256 与 SubModule Version。重新读取最终包、ZIP 条目和安装文件逐项比较，不靠文件名或“脚本刚跑过”。源包保留 `source/*.blend, *.fbx` 与 `tex/*.png` 的层级；FBX 外部贴图相对路径也必须能在解压后解析。

已安装模块备份/更新只针对自己的目录。Windows 任何递归移动或删除前解析绝对路径并确认目标在预期范围内，用同一种 shell 和 LiteralPath 完成，不把枚举结果转给另一种 shell 删除。用户自己测试时只提供更新包和重点观察事项，不启动游戏来代替测试。
