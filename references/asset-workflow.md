# 绑骨、布料与资源格式

## 原生绑定与网格适配

从已安装游戏读取骨骼名称、父节点、顺序、rest matrix 和原生动作。当前 human skeleton 是 28 骨，其他版本/自定义骨架必须按实际导出确定。示例索引：pelvis 0；左/右 thigh 1/5、calf 2/6、foot 3/7；spine 9–11、neck 12、head 13；左右臂组 14–20 / 21–27。不要把数字当跨版本约定。

本机 mbtool 骨架 JSON 的矩阵是列主序：`np.array(rest).reshape(4, 4).T`。当前 reader 的最后齐次行有无用值，解析时设为 `[0,0,0,1]`；换 reader 先确认格式。世界矩阵逐级 `parentWorld @ local`；离线 skin matrix 是 `poseWorld @ inverse(bindWorld)`。当前动画以 rest translation 加局部旋转、根平移重建，某些第 0 帧是绑定姿态，不是运动帧。

1. 用头顶、脚底、骨盆、肩/肘/腕、膝/踝等实际解剖点适配模型，验证单位和面向。天香原模型需要 cm→m 的 `0.01`，目标 +Y 为前方；其他模型先测量，不能照搬。
2. 无骨模型按骨段距离/胶囊得到权重初稿，再根据解剖区、连通块、部件类型限制候选骨。长袖飘带不能因靠近大腿就绑到腿；眼睛、睫毛和头饰通常随头，下颈再过渡。
3. 保留原生 skeleton rest/bone order，通过网格变形适配。肩、肘等过渡采用连续影响区域，避免刚性部件之间出现断层。
4. 导出每顶点最多四个影响。归一化后量化到 byte，取整并把余数分配到最大权重，确保和为 255；所有索引在实际骨骼范围内。
5. 验证绑定姿态与原生动作。FBX 关闭自动 leaf bones，避免应用 Armature 后再次蒙皮；坐标转换只做一次。UV 或 corner normal 不同的角点需要拆成独立导出顶点，重新计算法线和切线。

## 原生动画离线预览

数据来自**本机游戏的 TPAC**，不需要启动游戏。当前工程通过 mbtool 读取 `Modules/Native/AssetPackages/skeletons.tpac` 的 `human_skeleton`，从 `animations.tpac` 导出动作的局部旋转关键帧和根平移；动作资源名称与 XML 中的 action/clip 名可能不同，先定位实际资产，必要时用 `animation_clips.tpac` 查引用与播放时长。

1. 用 `skeljson`、`anim` 导出骨架和动作 JSON。检查目标骨架、骨骼数、实际关键帧和覆盖区间；命令返回成功不代表有可播放的数据。本次某些资源只有名称、没有旋转关键帧，不能将默认单位四元数生成的姿态计为有效动作检查；换有数据的动作或使用能解析对应 clip 数据的工具。
2. 用 `exportmod` 从**最终交付 TPAC** 重新导出每个 LOD，读取实际顶点、四骨索引和 byte 权重。数值验证使用这些数据；修改、重打包之后重新导出，避免验证旧缓存。
3. 按骨骼父子关系计算每帧世界姿态，再算 `skin = poseWorld @ inverse(bindWorld)`。当前解析器用 rest 的局部平移、关键帧局部旋转及根平移重建姿态。顶点按归一化后的量化权重做线性蒙皮：`posedVertex = sum(weight * skinMatrix * bindVertex)`。
4. 检查第 0 帧是否为绑定姿态；根据实际数据跳过异常绑定帧。关键帧时间轴不一定以秒为单位，制作播放预览或视频时用 clip 时长确定速率，不能直接把帧编号当秒数。
5. 当前 Blender 图片预览打开可编辑 Blend，移除预览对象的 Armature 修改器，将上述计算的姿态写入网格，避免再次蒙皮。法线同步按骨骼旋转变换并归一化；需要变形后重新计算时处理好跨部件接缝法线。隐藏可选 Cloth 副本，基线与修改版使用一致的镜头、光线和原始贴图。这种流程是在 Blender 渲染采样姿态，并没有自动把游戏动画导入为 Blender 时间轴动画。
6. 扫描完整动作周期并选最差帧渲染。最终 TPAC 上检查颈缝、关节压缩、顶点有限性、裙摆顶点与三角面内部的腿部接触估计。握持返修再检查手掌是否稳定跟随原生手骨、前旋是否挪动手腕；武器挂点属于骨架，移动网格不能代替移动挂点。
7. 报告实际动作名称、有效帧数、LOD、包 SHA256 与检查方法；前后对比明确版本。渲染若使用源 Blend，应说明它是源文件预览，并用最终 TPAC 回读结果证明导出后的模型、权重与修正目标一致。

本机解析入口是 `D:\gpt-mb2-mod\previewer\baker\skeleton.py`、`animation.py`，最终几何读取为 `D:\gpt-mb2-mod\tools\georead.py`。天香示例渲染脚本为 `tools/render_motion_review.py`；`-- --grip` 使用 `build/grip_baseline/rigged.blend` 和 `reports/grip_twohanded_*.json` 做手部返修对比，`tools/verify_grip.py` 检查最终权重与姿态。基线文件和动作路径是此工程的专用约定，新工程先适配或从对应 Git 版本恢复基线，不能把缺少输入的脚本直接当通用播放器。

**验证边界**：这条流程没有运行游戏的布料求解器、武器 IK、手部握持形变、角色体型缩放或战场碰撞。没有读取/挂载武器的预览不能证明手已经握住具体武器；胶囊代理也不能证明游戏里没有穿模。Blender Cloth 预览是另外一种求解器，需单独标注。游戏中的最终表现继续由用户测试。

## 头颈、肩臂与身体返修

头颈分属不同装备网格时，边界相同位置的顶点应具有相同的骨骼影响和量化结果；静止时重合但权重不同，跑动会裂开。跨皮肤部件共享面积加权法线可改善阴影接缝，无需破坏原 UV。LOD 简化后重新检查边界位置、权重和法线；保护组仍可能无法保边，必要时让相关皮肤片保留完整几何，而不是接受重新出现的裂缝。

颈长不协调时先查胸椎、锁骨、颈部的源标记与映射关系。天香案例曾修正过高的胸椎标记，再整体下移刚性头部 14 mm；这不是新模型的默认缩颈量。

手臂前旋以目标肩为支点，先确定真正的前方和旋转符号。可用臂骨权重之和作为平滑影响量，在肩/胸区衰减；不要挪动游戏 skeleton 来修外观。用户要求新增角度时从原始输入设置新总角度，避免叠加误差。验证臂长、手的位置、与基线的实际角度，握持兼容性仍需游戏确认。

胸到腰的体积变化使用局部高度/横向影响场，身体、衣服使用同一场，保留头、腿与下裙摆。采用增量位移 `P + influence * displacement`；零影响点原样保留，避免围绕中心做“乘 1”也引入浮点漂移。重新处理接缝法线。

天香 v1.3.0 示例：前一版前旋 6°，追加 20° 后总 26°；胸腰最大宽度 1.08、前后厚度 1.05，渐变过渡。只能作为这次返修的复现参数。

## 游戏布料与裙摆防穿模

Bannerlord 的顶点颜色 Alpha 表示相对**蒙皮锚点**可移动的距离，0 为固定；距离还受 mesh multiplier 影响。蒙皮作用于全部布料顶点，因此错误锚点会限制物理能纠正的范围。官方也区分直接模拟与独立代理网格映射模拟。[TaleWorlds 布料说明](https://moddocs.bannerlord.com/editor/resource-editors/cloth_simulation/)

- 先做可信的无物理蒙皮。长裙腰部固定；沿高度平滑增加同侧 thigh/calf 权重，左右交界连续，避免后片左右撕扯和裙摆过度随踝。检查向后抬脚时的小腿与鞋跟。
- 适当增加裙摆内部余量，针对局部后膝/脚跟调整，不能只把全部裙子向外吹大。大三角形内部也会穿透，检查三角形质心/面采样，不能仅检查顶点。
- 再画 Alpha：腰、接缝、脸、鞋等不应随意模拟；活动区域有渐变。谨慎给较小位移，较高抗拉与锚定、适度阻尼，较低惯性与风，结合实际拓扑调节。
- 当前示例使用 `uses_cloth_simulation`、每顶点 Colors1.A、ClothingMaterial、`human_body` 碰撞体，仅 LOD0 开启直接布料，其余 LOD 依赖蒙皮。天香裙摆最大约 0.04 m，经 byte 量化约 10/255；长飘带约 0.11、长发约 0.028。这些是示例值，不是所有布料的最佳值。
- 高面数、多层或双面拓扑可考虑代理网格。代理要与渲染网格合理贴合，并检查映射和碰撞；不能声称只加 Blender Cloth 就完成映射。若通过官方工具生成 `.tcc/.tcm`，交付相关数据并检查关联。当前离线路线未交付这些预处理缓存，不能将其描述为完整编辑器烘焙流程。
- `UnknownBool*`、`UnknownInt*` 是第三方 reader 的占位名。没有对应版本的读写源码/原生样本证据时，不能宣称其等于编辑器的 Precise Simulation 或 Dummy Collision Particles。

Blender 内若另建 Cloth 预览副本，放独立隐藏集合，不导出重复几何；明确预览求解器与游戏求解器不同。离线动画、蒙皮胶囊距离和有符号面距离是筛查工具，不是“游戏里已消除穿模”的证据。

## 材质、贴图和顶点 Alpha

透明裁切通常由纹理 Alpha 与 `alpha_test` 阈值控制；蒙皮材质还需正确 vertex layout。参照实际同类材质，并阅读 [TaleWorlds 材质编辑器](https://moddocs.bannerlord.com/editor/resource-editors/material_editor/)。

本机原生 `Shaders/Sources/pbr_standart_pixel_functions.rsh` 中，标准路径会在未设置 `g_mf_disable_vertex_color_alpha` 时将纹理 Alpha 乘顶点 Alpha。因此，当 Alpha 同时保存布料活动距离时，固定点的 0 或小活动值会把头发/衣服裁掉。给实际使用这套规则的材质设置 **Material.ShaderMaterialFlags** 中的 `disable_vertex_color_alpha`，保留纹理 Alpha、原 AlphaTest、BlendMode 和布料数据。不要加到普通 Material.Flags 或 Mesh.MaterialFlags，也不要把 A 改成 255 来修显示。

优先保留输入颜色与裁切信息。BC1/DXT1 可用于不透明贴图，BC3/DXT5 保留一般 Alpha，BC5 用于适合该通道约定的法线；生成完整 mip 链并验证最终解码。只有颜色图时可提供保守的平法线/材质参数，不能宣称补齐了原作 PBR。天香曾对特定纱质贴图调整 Alpha 下限，不应强加到新模型或裁切贴图。

## TPAC 的易错点

- 模块、MetaMesh、材质、贴图、包/资产 GUID 使用自己的命名空间；同一模块版本间保持稳定，其他模型不能复用 `tx5_*` 与 GUID。先在当前游戏定位兼容的网格/材质/贴图模板，再复制类型化字段并覆盖自身数据。
- 某些 TpacTool.Lib 对象保存缓存 `_rawMetadata`。修改类型化字段后若仍复用旧字节，保存文件看似成功却没有改动。当前补丁清掉缓存再保存；这是库版本相关处理，必须读取最终包和做元数据往返验证。
- 当前修补过的 VertexStreamData writer 中，offset 表普通为 `26*8=208` 字节，有 QTangent 时 `28*8=224`；第一个数组 offset 从表后开始。索引流只写一次数量前缀，避免 `WriteStructArray` 再写一个。索引位宽/用户标记必须一致。这些记录用于排查当前 serializer，不能随意对其他库二进制补丁。
- “第三方 reader 能打开”不足以证明引擎能读取。将最终顶点流、索引与原生样本布局对照，做校验和和元数据检查，再由用户测试引擎。
- 当前 LOD 比例 `1 / .58 / .28 / .12` 仅作起点；按实际轮廓、颈缝、面数和远景表现选取，检查每级输出。
