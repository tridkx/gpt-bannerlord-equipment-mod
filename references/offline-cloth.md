# 离线布料编译与 LOD

本机工作区 `D:/gpt-mb2-mod2/tools/cloth_compiler/` 已维护共用直接布料编译器，完整命令、格式和边界见该目录 README.md。无需 Computer Use 或官方编辑器；遇到已支持的直接模拟问题，先使用现有工具核查与生成数据。该工具不实现代理网格映射，不替代正确的蒙皮、固定根部、碰撞体和材料设置。

## 已验证的范围

原生布料段类型 `b97e0f10-df49-4666-8f1d-ada6630d4b4e`：七个原生样本已完整解析并逐字节往返，包含约束、无写冲突的并行分组、压缩位置/法线、顶点映射、活动距离、骨骼和锚点。明玉 v1.0.4 在 2026-10-09 获得用户反馈“可以生效，但是只有很近的时候才生效”，仅确认近处有效，不覆盖 LOD1、远处、所有动作、碰撞或性能。助手未启动游戏。此数据格式和三角网络算法没有复刻原生重构/经纬分类，不直接保证其他模型或引擎版本效果。

天香 T5 v1.6.0 的直接模拟试验虽通过离线检查，用户复测仍报告裙子和袖子拉伸；该模型未通过游戏验收，不能从明玉近处有效推断所有模型可用。异常分流及历史证据见 [裙摆注意事项](asset-workflow.md#注意事项历史天香裙摆方案)。

## 复用方法

- 共用代码在工作区根 tools/cloth_compiler；各模组 tools 保存自己的 cloth_policy.json、资源名、GUID、材料、布料 LOD 与验证断言。不要把明玉网格编号、固定带宽或四网格数量套给新模型。
- 先生成带运行时 Alpha 和蒙皮的 TPAC，再用 NativeClothProbe 指定资产名导出网格 JSON，cook_cloth.py 生成自有约束，ClothPatch 指定 `--allow-metameshes` 插入到新输出文件。输入保留；构建缓存和输出放目标模组 build。
- 缺少固定根部时，共用默认策略是报错。仅对实际连接点允许固定策略；未确定连接位置时不要自动冻结长薄纱。显式策略的新增固定点保存在 manifest，它们覆盖求解 Alpha，不修改渲染 Alpha。
- 目前 Patch 要求编辑器顶点和运行时顶点顺序一致，共享位置权重一致；不同导入器需要适配并验证，不能直接按索引套用。
- 修改 TpacTool 外部加载数据后使用 MarkLongLive 保留到保存结束，避免弱引用被回收而丢失修改。重新读取最终包确认每个网格的数据都保存成功。
- 增量替换顶点/索引流时，核对实际 `TypelessDataSegments` 条目也已替换；仅赋值 Mesh 的流属性可能仍保存旧段。类型化元数据改变时核对所属 MetaMesh 的 `_rawMetadata` 缓存是否需清除。两项都是当前库实现相关处理，以最终回读为准，不能只看内存属性。
- 源几何、权重或 Alpha 改变后，重新编译相应位置、活动距离、映射、约束和锚点。逐级核对启用 LOD，比较求解 Alpha 与渲染 Alpha，显式新增固定点以 manifest 为依据；保留非目标数据和已接受的碰撞体。活动范围与碰撞检查见 [专题说明](cloth-collision.md)。
- 验证最终 blob 与生成字节一致、长度符合原始几何、映射/骨骼权重和压缩误差合理、锚点不跨连通片、分组无并行争写、全部预期 LOD 的固定点保留。再比较请求外的几何、材质、运行时 Alpha 和蒙皮；不要复制原生约束到不同网格。

## 距离反馈

用户报告只近处有效时，分别确认渲染 LOD 切换、各级是否有布料数据、引擎是否真正求解该级；每个启用 LOD 都要使用自身减面后的 Alpha、根部与约束。不能仅加 uses_cloth_simulation，也不能把 LOD0 约束直接挂到 LOD1。

[官方 LOD 文档](https://moddocs.bannerlord.com/asset-management/asset-types/meshes/)列出最高画质默认切换点 15、22.5、30、50、70、130、210 米，角色/环境质量会缩短距离。这些是官方参考值，不是某设备上的实测布料截止距离；未确认独立限距或实际 LOD 时明确保留不确定性。

工具迁移本身不更改模组版本、游戏模块或历史标签。使用源包时可由 mod.json.shared_source_files 声明共用工具文件，打包至 workspace_tools/cloth_compiler，保持 source/tex 相邻；不在工程创建或复制 skills。
